# Codex 续开发规则

## 总原则

1. 不要破坏现有 API 路径。
2. 新算法必须放在 `weather_diag/diagnostics` 或 `weather_diag/features`。
3. 所有阈值必须配置化，不能硬编码在算法里。
4. 每个天气系统输出必须包含：`feature_type`、`confidence`、`evidence`。
5. 自动文字分析必须基于结构化结果，不允许凭空生成。
6. 涉及符号正负的物理量必须在图例和文档里说明。
7. 新增功能必须提供最少一个测试或示例脚本。

## 代码风格

- Python 类型标注优先。
- 算法函数尽量纯函数化，输入 numpy/xarray，输出 numpy/GeoJSON。
- 不在 API 层写算法细节。
- 不在前端写业务诊断逻辑。

## 下一步优先级

1. 接入真实 EC 文件，修正变量映射。
2. 优化槽线/脊线/锋面候选算法。
3. 将 bbox 面替换为真实等值线或轮廓 polygon。
4. 引入 PostGIS。
5. 基于现有 MapLibre 前端完善瓦片化、等值线、风场和三维预留。
6. 加入模式探空与垂直廓线诊断。
7. 增加雷达/卫星/自动站实况订正。
